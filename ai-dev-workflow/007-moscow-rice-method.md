## 一、MoSCoW优先级排序法

### 1.1 方法概述

MoSCoW是一种功能优先级排序方法，通过四个分类确定功能重要性：

| 分类 | 含义 | 特点 |
|------|------|------|
| **M** (Must have) | 必须有 | MVP核心功能，缺失将影响产品价值 |
| **S** (Should have) | 应该有 | 重要但不紧急，提升用户体验 |
| **C** (Could have) | 可以有 | 长尾功能，锦上添花 |
| **W** (Won't have) | 不会有 | 可舍弃，不开发 |

1.2 分类标准

| 分类 | 判断标准 | 水印产品示例 |
|------|---------|---------|
| Must | 无此功能产品无法使用 | 底部边框水印、EXIF参数显示、图片保存 |
| Should | 功能缺失会降低满意度 | 天气水印、批量处理、透明度调节 |
| Could | 功能存在会提升满意度 | 自定义Logo、云模板同步、AI智能推荐 |
| Won't | 功能价值低，成本高 | 社交分享集成、复杂滤镜系统 |
### 1.3 MoSCoW工作流程
```
┌─────────────────┐
│ 功能需求池     │
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 人工初步分类   │ ← 按业务价值主观判断
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 输入AI评分   │ ← 提供功能描述让AI评估
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│ 综合得出结论   │ ← 人工审核AI评分结果
└─────────────────┘
         │
         ▼
┌─────────────────┐
│ 优先级排序     │
└─────────────────┘
```

## 二、RICE评分法
### 2.1 方法概述
RICE是一种量化评分方法，通过四个维度综合计算优先级分数。
| 维度 | 含义 | 权重建议 |
|------|------|--------|
| **R** (Reach) | 用户触达/影响范围 | 40% |
| **I** (Impact) | 功能实现后的价值/影响 | 30% |
| **C** (Confidence) | 实现信心/技术可行性 | 20% |
| **E** (Effort) | 开发成本/工作量 | 10% |
### 2.2 计算公式
```
RICE分数 = (Reach × R权重) + (Impact × I权重) + (Confidence × C权重) - (Effort × E权重)
```
**评分示例**：
| 功能 | Reach(1-10) | Impact(1-10) | Confidence(1-5) | Effort(1-10) | RICE分数 |
|------|-----------|-----------|---------------|-----------|---------|
| 底部边框水印 | 10 | 9 | 5 | 3 | 8.2 |
| 天气水印 | 8 | 7 | 5 | 4 | 6.7 |
| AI推荐 | 6 | 4 | 3 | 8 | 3.6 |
| 社交分享 | 4 | 2 | 4 | 2 | 2.8 |
### 2.3 RICE评分矩阵
```
┌─────────────────────────────────────────────┐
│           Reach    │ Impact  │ Confidence  │ Effort │ RICE  │
├─────────────────────────────────────────────┤
│ 高优先级  │ 8-10分 │ 8-10分 │ 4-5分  │ 1-3分 │ >6分 │
├─────────────────────────────────────────────┤
│ 中优先级  │ 5-7分  │ 5-7分  │ 3-4分  │ 4-6分 │ 4-6分 │
├─────────────────────────────────────────────┤
│ 低优先级  │ 2-4分  │ 2-4分  │ 1-2分  │ 7-10分│ <3分 │
└─────────────────────────────────────────────┘
```

## 三、人工 vs AI：谁来完成？
### 3.1 能力对比
| 任务 | 人工优势 | AI优势 | 推荐执行方 |
|------|---------|---------|---------|
| 功能需求收集 | 理解用户痛点 | 整理结构化需求 | 人工主导 |
| MoSCoW分类 | 业务价值判断 | 标准化分类逻辑 | AI辅助评分 |
| RICE评分 | 综合权衡 | 数值计算 | AI计算 |
| 最终决策 | 经验判断 | 数据参考 | 人工审核 |
| 优先级排序 | 直觉排序 | 算法排序 | AI生成 |
### 3.2 协作模式
**推荐模式：人工主导 + AI辅助**
```
人工：提出功能需求、判断业务价值
AI：根据需求描述进行MoSCoW分类和RICE评分计算
人工：审核AI结果、做出最终决策
```

## 四、如何让AI完成MoSCoW+RICE评分
### 4.1 AI输入模板
```markdown
## 功能规划请求

请根据以下功能需求，进行MoSCoW分类和RICE评分：

### 产品信息
- 产品名称：边框水印应用
- 目标用户：摄影爱好者、社交分享用户
- 核心价值：自由风格、专业水印、清爽体验

- 开发周期：8周
- 团队规模：2人

### 功能需求列表
1. **底部边框水印**：在照片底部添加参数条，显示机型、时间、GPS、拍摄参数
2. **极简边框水印**：单行信息条，适合快速分享
3. **天气水印**：显示实时天气信息
4. **批量处理**：多张照片批量添加水印
5. **透明度调节**：水印透明度可调
6. **自定义Logo上传**：用户上传Logo或签名
7. **AI智能推荐**：基于场景推荐水印风格
8. **动态照片水印**：支持各厂商动态照片格式
9. **云模板同步**：用户自定义模板云端同步
10. **社交分享集成**：一键分享到社交平台

11. **复杂滤镜系统**：多种滤镜效果叠加

12. **水印历史记录**：记录用户使用过的水印配置

13. **离线天气缓存**：无网络时显示天气

14. **多语言支持**：国际化适配

15. **企业定制功能**：为企业提供定制水印模板

```
### 4.2 AI输出格式要求
```markdown
请输出以下格式的结果：

## MoSCoW分类结果
| 功能 | 分类 | 分类理由 |
|------|------|---------|

## RICE评分结果
| 功能 | Reach | Impact | Confidence | Effort | RICE分数 | 排名 |
|------|-------|---------|------------|--------|---------|------|

## 最终优先级建议
- Phase 1 (Week 1-3)：[列出功能]
- Phase 2 (Week 4-6)：[列出功能]
- Phase 3 (Week 7-8)：[列出功能]
```

## 五、AI评分执行示例
### 5.1 Claude Code执行方式
**Prompt示例**：
```
请对以下功能进行MoSCoW分类和RICE评分。

功能：底部边框水印
描述：在照片底部添加参数条，显示机型、时间、GPS、光圈、快门、ISO等拍摄参数
用户价值：核心差异化功能，摄影爱好者刚需

评分：
- Reach: 10（所有用户都需要）
- Impact: 9（缺失则产品无价值）
- Confidence: 5（技术成熟）
- Effort: 3（3天开发）

MoSCoW分类：Must have
理由：MVP核心功能，无此功能产品无法满足用户需求

RICE分数：8.2
排名：第1
```

**AI实际输出**：
Claude Code会根据提供的模板，逐个功能进行评分和分类，生成完整的表格。

### 5.2 执行技巧
1. **提供足够上下文**：包括产品定位、用户画像、开发资源
2. **明确评分标准**：告诉AI各维度的评分范围
3. **要求输出结构**：指定表格格式便于对比
4. **人工审核**：检查AI的分类逻辑是否符合业务实际
5. **迭代调整**：如果AI分类不合理，调整评分后重新计算

## 七、注意事项
### 7.1 AI评分的局限
| 局限 | 说明 | 解决方案 |
|------|---------|---------|
| 缺乏业务理解 | AI不了解用户痛点 | 人工补充业务背景 |
| 数值主观 | AI评分可能偏高 | 设置合理范围、人工审核 |
| 忽略技术约束 | AI不了解技术栈 | 提供技术背景信息 |
| 忽略市场变化 | AI不了解竞品动态 | 提供竞品分析资料 |

### 7.2 最佳实践
1. **先做竞品分析**：让AI了解市场情况
2. **提供用户调研数据**：如果有用户反馈，一并提供
3. **明确技术可行性**：告诉AI哪些技术已成熟
4. **设置Effort上限**：避免AI低估开发成本
5. **人工审核决策**：AI是辅助，最终决策需人工

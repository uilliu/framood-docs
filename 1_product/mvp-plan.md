## 一、产品定位

### 1.1 产品概述

| 属性 | 内容 |
|------|------|
| **产品名称** | Framood（框有引力） |
| **核心价值** | \"自由风格，专业水印，清爽体验\" |
| **目标用户** | 社交分享用户（第一优先级）、摄影爱好者（第二优先级）、HarmonyOS NEXT用户（第三优先级） |
| **差异化定位** | 跨品牌风格自由选择 + 高度自定义 + 清爽无广告 + 本地隐私处理 + HarmonyOS首发 |

### 1.2 核心功能定位

- **主要场景**：用户从相册选择照片，添加边框水印，导出到相册
- **水印风格**：内置华为 Mate 80 系列风格模板，支持用户自定义素材
- **智能推荐**：自动识别 EXIF 机型信息，智能推荐匹配的水印模板
- **画质控制**：支持用户设置的画质参数导出

## 四、技术架构建议

### 4.1 平台选型

| 决策项 | 选择 | 理由 |
|--------|------|------|
| **目标平台** | HarmonyOS NEXT（单框架） | 用户明确需求，抢占鸿蒙原生应用空白市场 |
| **开发语言** | ArkTS + C++（Native层） | 鸿蒙官方推荐，高性能图像处理需要 Native 层 |
| **UI 框架** | ArkUI（声明式 UI） | 鸿蒙原生 UI 框架，跨设备适配能力强 |
| **图像处理** | Canvas + PixelMap + ImageEffect API | 鸲蒙原生图像处理能力，参考华为相机水印架构 |

### 4.2 核心技术依赖

| 技术模块 | HarmonyOS API | 说明 |
|---------|--------------|------|
| **照片选择** | @ohos.file.photoPicker | PhotoPicker 组件，支持相册访问 |
| **EXIF 解析** | @ohos.multimedia.image | ImageSource + EXIF 元数据提取 |
| **图像合成** | @ohos.multimedia.image + Canvas | PixelMap 创建 + Canvas 绘制水印 |
| **图片导出** | @ohos.file.mediaLibrary | MediaLibrary API 保存到相册 |
| **机型识别** | EXIF Model 字段 + 机型映射表 | 解析设备型号，匹配模板推荐 |
| **GPS 解析** | EXIF GPSLatitude/GPSLongitude | 提取 GPS 信息，可选逆地理编码 |
| **动态照片** | MVIMG 解析 + XMP MicroVideoOffset | 参考调研文档 281 的技术方案 |

### 4.3 模块架构设计

`
应用层 (ArkTS + ArkUI)
├── 照片选择器 (Picker)
├── 水印编辑页 (Editor)
├── 画质设置页 (Settings)
│
└── 水印处理服务 (WatermarkService)
    ├── EXIF 提取模块
    ├── 机型识别模块
    ├── 模板匹配模块
    ├── 水印合成模块
    └── 图片导出模块
│
Native 层 (C++) - 高性能图像处理模块
├── Canvas 绘制引擎
├── 大图异步处理
├── Bitmap Pool 内存优化
└── GPU 加速渲染（可选）
`

## 七、风险与应对

| 风险类型 | 风险描述 | 影响程度 | 应对措施 |
|---------|---------|---------|---------|
| **品牌版权风险** | 模仿华为等厂商水印风格可能涉及商标侵权 | 高 | 使用通用设计元素，不直接使用品牌 Logo；用户自定义素材自行承担授权责任 |
| **动态照片兼容性** | 各厂商动态照片格式差异大，兼容复杂 | 中 | MVP 阶段优先支持 MVIMG（华为/三星），其他格式分阶段支持 |
| **HarmonyOS 开发门槛** | 单框架鸿蒙开发学习曲线陡峭 | 中 | 使用官方 ImageEffect API |
| **EXIF 解析准确性** | 部分 EXIF 字段可能缺失或不标准 | 低 | 提供默认值兜底，允许用户手动编辑 |
| **性能问题** | 大图处理可能导致内存溢出 | 中 | 参考 Huawei 235 文档的 Bitmap Pool + SurfaceBuffer 优化策略 |
